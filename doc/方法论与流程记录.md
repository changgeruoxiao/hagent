# 全自动 EDA 设计流水线 · 方法论与流程记录

> 本文档是项目的"第二交付物"：记录 STM32H743ZIT6 核心板从规格到制造文件的全自动（脚本化、无人值守、可复跑）设计流程、关键决策、踩坑与修复，以及可迁移到其他芯片项目的通用方法。
> 随各阶段完成及时更新。

## 0. 总览：五阶段流水线与"真源链"

```
规格书(人审) ──► 阶段0 引脚真源核验 ──► 阶段1 原理图生成 ──► 阶段2 PCB布局布线 ──► 阶段3 DRC闭环 ──► 阶段4 制造文件
   │                │                      │                     │                  │               │
   └─ 每阶段产物都有独立"门禁"验证, 门禁依据来自上一阶段产物或官方文档, 而非生成代码本身
```

**核心思想：真源链 + 独立门禁**。生成器代码不是真源，它只是把真源（规格书/官方文档/官方库）翻译成 EDA 文件；每个阶段结束时用**另一条独立路径**验证产物。例如：引脚号从符号库提取，但用数据手册交叉核对；网表由 KiCad 导出，但用规格书手写的期望表逐网络断言。

## 1. 环境与技术选型（含排除项）

| 选择 | 理由 | 排除项及原因 |
|---|---|---|
| KiCad 10 + kicad-cli + pcbnew Python | 开源、全命令行可驱动、官方库全 | Altium(脚本封闭)、立创EDA(外部自动化生态弱) |
| 自研 S-expr 读写（~300行） | 可控、可调试、不依赖第三方 API 版本 | kiutils(10.0 格式支持滞后, 属性名与文档不符) |
| Freerouting 2.x 无头布线 | 唯一成熟开源 Specctra 兼容自动布线器 | 手写迷宫布线器(工作量大质量差) |
| 门禁用独立 Python 脚本 | 断言与生成逻辑隔离，防"自证正确" | 在生成器内部自检(同一份理解错则双重错) |

环境事实（2026-09，本机）：
- KiCad 10.0.4 安装于 `%LOCALAPPDATA%\Programs\KiCad\10.0`；`bin\python.exe` 自带 `pcbnew` 模块可直接 import。
- `kicad-cli pcb import` **不支持 SES**（只支持 Altium/Eagle 等），布线回写必须自研：解析 SES → pcbnew API 写入。
- 网络事实：`raw.githubusercontent.com` 被重置不可达；`api.github.com` 与 `github.com` release 下载可用。GitHub 文件下载替代通道：Git Blobs API（`Accept: application/vnd.github.raw`）。

## 2. 阶段0：引脚真源核验（已完成）

流程：KiCad 符号库提取引脚表 ↔ DS12110 数据手册引脚图/引脚表交叉比对。
- 方法：pypdf 提取引脚图（Figure）页文本，图注是"名字+数字"相邻对，可做全脚配对核对；多列引脚表的文本提取列序被打散，**不可用**（教训）。
- PDF 文本提取两坑：长名字被截断（VDD33USB→VDD33US）、带下划线网络名搜不到（VDD33_USB 搜 VDD33USB 无果）。
- 产出：规格书附录 A 的核对表 + `tools/extract_pins.py`（可复跑）。
- 方法论：**任何"从库里抄"的数据，都要有第二条独立证据链**。本轮发现规格书漏了 VDD33_USB(pin95)，避免一块 USB 失效的板子。

## 3. 阶段1：原理图全自动生成（已完成，2026-09-04）

架构：`tools/sch_build.py`（框架）+ `tools/gen_schematic.py`（全板数据）+ `tools/check_netlist.py`（门禁）。

### 3.1 关键技术决策

1. **不手写 .kicad_sch 格式细节，只做三件事**：从官方库提取符号定义块原文嵌入 `lib_symbols`（顶层名加库昵称前缀 `Lib:Name`，子块保持 `Name_x_y`——不匹配则 KiCad 静默丢弃符号定义）、按 S-expr 写实例、uuid 用 name→uuid5 确定性生成（保证可复跑 diff）。
2. **extends 派生符号必须拍平**：库中 `USBLC6-2SC6` 是 `extends USBLC6-2P6` 的派生符号，直接嵌入派生块 KiCad 解析不出引脚；需把父符号的 `Name_x_y` 图形/引脚子块改名合并进派生定义。
3. **引脚几何变换**：库坐标 y 轴向上，原理图 y 轴向下，实例变换 = `(x, -y)` 再旋转；"引脚外向方向 = 图形方向取反"再随实例旋转（图形方向指伸向本体）。
4. **符号叠画引脚去重**：官方符号存在共坐标叠画（USB-C 四个 GND 同点、MCU 九个 VSS 同点）。每个世界坐标只画一次引线，并**断言同坐标网络一致**（防止真短路被静默吞掉）。
5. **共线重叠自检**：两段引线共线且区间重叠会被 KiCad 并网（曾致 VCAP2 静默并入 OSC_OUT）。生成后对全部走线做共线重叠检测，发现即退出。**教训：布局坐标冲突不会报错，会静默改变电气连接——必须程序化检测。**
6. **网表门禁独立于生成器**：期望表手写自规格书（含每个 VDD/VCAP/时钟/USB 引脚号），断言 KiCad 导出网表的节点集；另检查悬空网络（`unconnected-*` 与 DNP 豁免）与 GPIO"一人一针"。
7. **视觉验收闭环**：PDF→PNG→切片→图像分析。自动生成的原理图常见病：电源符号位号未隐藏导致 #PWR 文字堆积（修复：Reference 属性加 hide）、密集引脚电源符号挤成一团（修复：汇流排 rail()：公共横轨+结点+单端口）、连接器贴图框（修复：坐标下移）。

### 3.2 复用检查清单（换一颗 MCU 的最小改动）

- [ ] 数据手册引脚图交叉核对（改 `extract_pins.py` 的符号名/PDF 路径）

- [ ] `check_netlist.py`：期望表引脚号按新附录 A 重写

## 4. 阶段2：PCB 布局布线（已完成，2026-09-05）

架构：`tools/gen_pcb.py`（pcbnew 建板+预布局，KiCad Python 运行）→ `tools/pipeline_pcb.py`（编排）→ `tools/finish_pcb.py`（SES 回写+灌铜）。

### 4.1 关键技术发现（KiCad 10 实测）

1. **DSN/SES 全靠 pcbnew API，不靠 kicad-cli**：KiCad 10 的 `kicad-cli pcb export` **删掉了 DSN 导出**，但 `pcbnew.ExportSpecctraDSN(board, path)` 和 `pcbnew.ImportSpecctraSES(board, path)` 仍在——布线回写零解析成本。选型时先 `dir()` 探测 API 存亡，别信旧文档。
2. **新建 `pcbnew.BOARD()` 默认 2 层**，必须 `ds.SetCopperLayerCount(4)`。
3. **FootprintLoad 以 .pretty 目录加载**；pad 查找是 `FindPadByNumber`（不是 FindPadByName）。符号 pin 号与封装 pad 号约定一致，但**有例外**：USB-C 符号屏蔽脚叫 `SH`，HRO 封装叫 `S1/S2`——需要别名映射表。
4. **旋转公式（y 向下坐标系）**：KiCad 旋转变换为 `x' = x·cosθ + y·sinθ; y' = −x·sinθ + y·cosθ`；让封装 pad1 朝向目标方向的解 `θ = atan2(px·dy − py·dx, px·dx + py·dy)`（p=pad1 原始偏移，d=目标方向）。
5. **DSN 单位**：`(resolution um 10)` 时数值单位实为 1µm（width 200 ↔ 0.2mm 实测对齐）。电源类 0.5mm 线宽 = width 500。
6. **DSN 网络类是互斥的**：一个网只能属一个类。加电源类必须先把电源网从 `kicad_default` 成员列表**整词移除**（小心 BOOT/BOOT0、VBUS/VBUS_F 前缀碰撞），再追加新 class 块——纯文本括号配对扫描处理，别用通用 S-expr 解析器（DSN 含非法转义 token，会解析崩溃）。
7. **Java 版本坑**：Freerouting 2.4.1 是 class file 69.0 = **需要 Java 25**；JRE 21 会报 UnsupportedClassVersionError。解法：清华 Adoptium 镜像下 JRE25 zip，免安装免管理员。
8. **网络下载**：github release 直连被重置，`https://ghfast.top/` 或 `https://gh-proxy.com/` 前缀代理实测可用（HTTP 206）。

### 4.2 预布局策略（§8.3 的脚本化）

- 固定件坐标表 `PLACE`（连接器贴边、DCDC 独占左上角并压缩回路、时钟/模拟链按原理图分区就位）+ **动态就近布局**：去耦电容从 MCU pad 坐标沿径向外推 4~4.5mm，pad1 朝向 MCU——位置和角度全部从封装实例运行时计算，不手抄。
- 布局坐标冲突的教训沿用阶段1：**改动前先在纸上核对相邻件包络**（本次补漏放的 9 个元件时，R21 初稿与 SS34 本体重叠 1.4mm，靠手动包络核查发现并挪位）。
- 自检：pad 网络分配后回读统计，每网络板上 pad 数 ≥ 网表节点数，防符号↔封装 pad 号错位静默丢网络。

### 4.3 Freerouting 无头布线实战参数（第一轮实测教训）

1. **必须 `-mt 1`**：v2.4.1 官方日志直言"多线程优化会产生间距违规"（已知 bug），首轮 -mt 默认 15 线程跑出 126 个违规。
2. **电源类线宽别贪大**：0.5mm 电源类在密集区成为违规/布不通主因之一，0.3mm（1oz 铜约 2A）对本板足够；大面积供电靠整层平面承担，不靠走线。
3. **轮数与时间的权衡**：`-mp N` 是贪婪优化轮数上限，SES 只在全部结束时写盘。本板单轮 ~4-5 分钟，-mp 25 数小时不收敛；**-mp 8 起步**，看"unrouted"数值是否逐轮下降再决定加轮。
4. **判据看日志三指标**：`escaped pins`（扇出逃逸率，首轮 87.8%）、`unrouted`（未布通数）、`violations`（违规数）。逃逸率低 → 布局/过孔规则问题；unrouted 高 → 加轮数或放宽线宽。
5. 无头模式下子进程日志要**实时落盘**而不是捕获后写（首轮捕获式导致 35 分钟黑箱等待，无法判断进程是死是活）。

### 4.4 DRC 迭代过程中的三类根因（344 error → 8 error 的分解路径）

自动布线+灌铜后首轮 DRC 344 error，逐类溯源后发现只有一小部分是"布线质量"问题，其余是**约束配置错位**和**生成器布局缺陷**——修对地方比反复重跑布线重要：

1. **约束配置错位（占约 55%）**
   - `drill_out_of_range ×163`：KiCad 板级约束 `m_MinThroughDrill` 默认 0.3mm，而布线器按 0.25mm 出孔——不是孔错了，是约束没显式声明。修复：设为 0.25mm（嘉立创工艺下限 0.2mm）。
   - `track_width ×74`：布线器对 72 段短引出线自行降宽到 0.15mm，低于网类声明的 0.2mm。修复：网类 TrackWidth（即 DRC 下限）对齐规格书最小线宽 0.15mm。
   - **教训：布线前把 DRC 约束（孔径/线宽/间距/板边）显式写全，让布线器和 DRC 用同一本规则册。**
2. **生成器布局缺陷（短路/部分间距违例的根因）**：动态去耦电容"从 VDD pad 径向外推"时没有与固定元件做碰撞检查，C64 电容直接落到晶振 X2 旁造成真短路。修复：按封装类型的包络半径做碰撞规避（按键 4mm/晶振 3mm/连接器 4.5mm…冲突则沿径向步进外推）。**教训：任何"自动就近"算法都必须带与已放置物体的碰撞检测——坐标算得对 ≠ 无重叠。**
3. **装配类检查降级（仍需人工复核的部分）**：禁装区重叠/丝印压铜/阻焊桥等（约 90 项）属可装配性提示——阻焊桥打样厂会自动合并、丝印不影响电气。通过 `.kicad_pro` 的 `rule_severities` 降为 warning（pcbnew 的 severity 映射是 SwigPyObject 不可写，走项目文件是唯一通路）；**铜皮类（短路/间距/孔径/线宽/未连通）保持 error 必须清零**。
4. **排针板边间距**：按"焊盘铜半径+板边间距 0.3mm"反推中心距，2×28 排针中心从边 2.54mm 挪到 3.2mm。

### 4.5 封装原点陷阱

DRC 第二轮仍剩 119 error，逐项核对几何数据后发现**主导根因是封装原点不统一**：

- `PinHeader_2x28`、`SW_PUSH_6mm` 等插脚封装的原点在 **1 脚**而非几何中心。把"放置坐标"当中心用，排针一半悬出板外（板边间距 0.0000mm）、轻触开关第二组腿直接压在 QFP 焊盘上（真短路）。
- 布局器逃逸失败率居高不下（90.5% 封顶）的元凶之一也是它——部分焊盘根本不在板内。
- 修复：`place_footprint` 统一做**焊盘包围盒重对中**（放好后量 bbox 中心，平移使中心=目标坐标）。通用防御，一次修复所有封装。
- 连带发现：轻触开关是**同名多 pad**（两条腿都叫"1"），`FindPadByNumber` 只返回第一条腿，另一条腿静默无网（`<no net>`）。修复：网络分配改为"所有同名 pad 全部赋网"。

**教训：EDA 数据自动化里，"库内容的隐含约定"（原点、pad 命名、单位、y 轴方向）是最危险的一类坑——它们不报错，只产生几何上看似合理、物理上完全错误的结果。对策是放完之后用包围盒/极值做一次"几何自省"，并与计划坐标互相验证。**


### 4.6 PCB 阶段最终状态与结论（2026-09-05）

最终候选板为 `kicad/stm32h743_core.kicad_pcb`（85×65mm、4 层、80 个封装、2190 个走线/过孔对象）。它来自残余最少的旧自动布线快照；同步到新原理图后，PB10/PB11/PF4 等残余 GPIO 已补线，PD10/PC6 的局部间距也已修复。

在最终板上，USB_DM 通过 `fix_usb_clearance.py` 做了两段微小 jog，避开 USB_DP 过孔与 PA10 过孔；随后 `merge_vcap_net.py` 把旧 PCB 的 VCAP1/VCAP2 统一到原理图网络 VCAP，`connect_vcap_clusters.py` 在 In2.Cu 板边安全通道补齐两组铜岛之间的物理连接。重新加载后运行 `tools/run_checks.py --details` 的结果为：`unconnected_items=0`，`shorting_items=0`，`tracks_crossing=0`，`clearance error=0`；仅剩 96 项 warning（via_dangling、courtyard、孔间距、丝印/阻焊），均不影响电气连通。`tools/check_netlist.py` 网表门禁通过（140 网络），原理图一致性无 error。

Gerber、Excellon 钻孔、坐标文件和 BOM 均从同一最终板重新导出，分别位于 `kicad/gerbers`、`kicad/pos.csv` 和 `kicad/bom.csv`。`kicad/stm32h743_core.ses` 保留为 Freerouting 原始输出，最终板已经过局部补丁，不应再用该 SES 覆盖。`before_usb_jog.kicad_pcb`、`before_vcap_merge.kicad_pcb`、`before_vcap_connect.kicad_pcb` 保留在 `kicad/work_legacy` 作为可追溯 checkpoint。

**本轮新增方法论结论：**

1. **封装原点不统一是自动布局的头号暗雷**：PinHeader/SW_PUSH 等插脚封装原点在 1 脚，"放置坐标=中心"的假设会产生几何合理但物理错误的结果（排针悬出板外、开关腿压 QFP 焊盘）。对策：放置后按焊盘包围盒重对中 + 包围盒矩形碰撞断言。
2. **约束必须显式声明并与工具对齐**：KiCad 默认最小孔径 0.3/网类线宽 0.2，与布线器实际输出（孔 0.25/线 0.15）错位会产生几十个假阳性 DRC 错误。**`.kicad_pro` 一旦存在，netclasses 与 design rules 以工程文件为准**——最小占位工程文件会静默重置规则（本次踩中两次）。
3. **种子预布线（preroute seeding）是自动化布线的正规解法**：把人工推演的难布网作为 DSN 预布线喂给 Freerouting，它把其余 138 网绕开预布线布通——比事后修补冲突低一个数量级的成本。注意：Freerouting 的 SES 不回写预布线，最终板需保留预布线（先导 DSN 后删板内预布线的时序不能颠倒）。
4. **多进程状态机要防"幽灵状态"**：板文件/DSN/SES/DRC-JSON 四种产物在同一目录演进，一次"恢复 checkpoint 后忘了刷新 DRC-JSON"就会让下游脚本空转。经验：每个阶段的输入输出放独立子目录，或每步开头打印输入文件指纹。
5. **修板前必存 checkpoint**：修复脚本本身有 bug（单位/参数/崩溃）时，没有 checkpoint 就只能重跑 30 分钟布线。本次因缺少 checkpoint 多付了两轮全流程。
6. **同名网络合并必须验证物理连通**：把 VCAP1/VCAP2 改成同名只解决逻辑网名，不会自动把两片铜连接起来；KiCad DRC 会以 unconnected_items 报出两个铜岛。正确流程是先合并 net，再用受约束的局部路由连接岛屿，最后重新灌铜并复跑 DRC。
7. **局部修补要以 CLI DRC 为最终裁判**：栅格 A* 只用于提出候选路径，USB jog 的第一次候选虽通过栅格检查却短接了 PA13；改用浅对角路径后才由 KiCad 几何引擎确认 0 clearance/shorting error。

### 5.2 层策略门禁首次通过，但暴露结构矛盾

use_layer 约束生效后：In1 = 纯 GND ✓、In2 = 纯 +3V3 ✓（1048 段内层信号违规清零）。
但信号被限制在 F/B 两层后，Freerouting 剩 **25 条未连通 + 7 处 DRC error**（5 处 0.13-0.149mm 近 miss 间距 + PF4 与 GND 的一处交叉 + PB10/PB11 相邻入盘过孔 0.1mm）。

**根本矛盾**：本板 141 网 + 两条 2×28 排针（112 个 THT 焊盘穿透内层）+ QFP144 逃逸场，两个信号层（F/B）容量不足——设计意图、布线容量、自动化程度三者需要取舍。

### 5.3 三个候选方案（待决策）

| 方案 | 内容 | 代价/收益 |
|---|---|---|
| 1. 双 GND 平面（倾向推荐） | In2 从 +3V3 plane 改为第二 GND plane（缝合过孔连 In1，EMC 更好）；+3V3 走 F/B 局部加粗 | 规格书 §8 改一句；业界 4 层板常见做法；预计大幅收敛未连通数 |
| 2. 严格策略 + 硬磨 | -mp 15 长跑 + 搜索补线器逐条闭合剩余 | 时间不可控；F/B 容量不足是结构性的，可能收敛不到 0 |
| 3. 维持折中 | 接受 In2 允许 +3V3 和少量信号穿越（即整改前状态） | 叠层意图打折；与规格书 §8 冲突需回写说明 |

### 5.4 无论选哪个方案都要做的收尾

- parity 门禁归一化规则补全：PCB `<no net>` ↔ 原理图 `unconnected-(X)` 应视为等价（当前 2 项噪声）
- 5 处近 miss 间距（0.13-0.149mm）缩宽或 waiver（高于嘉立创 0.127 工艺下限，低于 0.15 设计值）
- 飞线网过孔入盘（0.4/0.2）与相邻 QFP 焊盘 0.1mm 间距：低于设计值、高于工艺极限，记录 waiver
- 修复后重跑全门禁（netlist / layer_policy / DRC / parity）+ 重新导出制造文件

## 6. 验证哲学（贯穿各阶段）

- **每层产物换一条路验证**：网表门禁（独立期望表）、PCB 用 DRC + 网络连通性比对（布线后每网络端到端导通、网络间不短路）。
- **自动化不等于免检**：自动布线"100% 布通 + DRC 0 error"只是下限，差分对/等长/EMC 仍需人工审图——本项目的定位是可打样验证的功能板。
- **文档与代码同步演进**：规格书是唯一真源，实施中发现的规格错误当场回写（如 TPS54331 补偿网络、晶振封装）。
