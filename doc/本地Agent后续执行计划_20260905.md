## 6. P1：层策略不要直接改成“双 GND”来解决布线拥塞

当前 WIP 文档方案 1 提议：

```text
F / GND / GND / B
```

但如果普通信号仍只允许 F/B，这不会增加信号布线容量，反而让 +3V3 也更多占用 F/B。

因此本地 Agent 不应把“双 GND”作为“更容易自动布通”的默认结论。

建议做两个可比较实验：

### A. 严格 4 层基线

```text
F      Signal
In1    solid GND
In2    +3V3 plane
B      Signal
```

记录：未连通数、DRC error、Freerouting passes、via 数、总线长。

### B. 受控混合 L3

```text
F      critical/high-speed signal + local power
In1    solid GND (hard invariant)
In2    +3V3 pour + approved low-speed GPIO
B      general signal
```

约束：

- In1 永远禁止普通信号；
- USB / clock / SWD 等关键网禁止进入 In2；
- In2 只对白名单低速 GPIO 开放；
- +3V3 保留连续性门禁，不能被切成不可接受的窄颈/孤岛。

比较 A/B 后再决定正式层策略。

如果实验目标允许增加层数，再建立 6 层参考基线，而不是凭感觉判断 4 层策略优劣。
